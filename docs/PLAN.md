## Phase 2: geometry core + library + validation + guide (terminal A)

### 2a. `app/fold_utils.py`
- `build_fold(segments: list[(p1, p2, assignment)]) -> FOLD`
  - Add the square boundary as "B" edges.
  - Compute every pairwise intersection and split segments at them.
  - Merge vertices within SNAP.
  - Remove zero-length and duplicate edges; for duplicates, keep M/V over F over B.
  - Build `faces_vertices` by planar face traversal (sort half-edges by angle at each vertex, walk next-edge), dropping the outer face.
- Helpers: `vertex_neighbors_sorted(fold, v)` (by angle), `is_boundary_vertex`, `face_adjacency(fold) -> {(f1, f2): edge}`, `merge_collinear_lines(fold) -> list of full lines` (group edges with the same line equation; return endpoints, edge ids, and assignments).
- `fold_to_svg(fold, highlight_edges=None) -> str`. Colours: M red #e53935, V blue #1e88e5 dashed, F grey, B black.

### 2b. `app/validate.py`
- For each interior (non-boundary) vertex with incident creases (M/V only):
  - **Maekawa:** |#M − #V| == 2.
  - **Kawasaki:** sort the crease angles and compute the sector angles; the sum of alternate sectors must be π ± 1e-4. Even degree is required.
- Return `{ok, vertices: [...]}` with human-readable reasons, for example: "Maekawa: 3 mountain vs 3 valley (difference must be 2)".
- Note in a docstring: these are local (necessary) conditions. Global flat-foldability, meaning layer order, is NP-hard (Bern & Hayes 1996) and out of scope.

### 2c. `app/library.py` — models generated by code (no hand-drawn files)
Each model returns a dict with `id`, `title`, `category`, `description`, `segments`, and an optional `extra_steps`, and is built with `build_fold`.
**Each model must pass `validate` in tests. If a model still fails after two fix attempts, drop it and continue.**
- **bases:**
  - `kite-base`:
    - Diagonal (0,0)–(1,1) is F.
    - Valley lines (0,0)–(1, tan22.5°) and (0,0)–(tan22.5°, 1).
  - `preliminary-base` (square base):
    - Both diagonals and both book folds through the centre.
    - Choose assignments so the centre satisfies Maekawa: diagonals V, three book-fold rays M and one book-fold ray V. Split lines into rays at the centre so the rays can differ.
  - `waterbomb-base`: the inverse of the preliminary base (swap M and V).
  - `fish-base` (stretch): kite folds on both diagonal ends; derive coordinates with 22.5° geometry.
  - `bird-base` (stretch): the standard bird base CP (a preliminary base with petal folds, 22.5° geometry).
- **tessellations:**
  - `pleat-8`: 7 parallel vertical lines at k/8, alternating M/V.
  - `miura-ori`: a 4×4 Miura-ori. Horizontal zig-zag lines with parallelogram cells (offset 0.06), vertical-ish creases alternating M/V per row so that every interior vertex has degree 4 and passes Maekawa and Kawasaki.
  - `square-twist` (stretch): the classic square twist on a 4×4 grid.
- **modular:**
  - `sonobe-unit`: the Sonobe unit CP.
  - `extra_steps`: one "assembly" step explaining how three units interlock into a triangle, and six units into a cube.

`thumbnail_svg` is `fold_to_svg(fold)`.

### 2d. `app/guide.py`
- **Lines:** use `merge_collinear_lines`. A line is *edge-to-edge* if it spans boundary to boundary.
- **Steps, in order:**
  1. **reference:** edge-to-edge lines through the centre (0.5, 0.5). Order: book folds, then diagonals.
  2. **precrease:** the remaining edge-to-edge lines.
     - Group by direction (0°, 90°, 45°, 135°, then others).
     - Within each group, order by grid level: distance from the centre as a multiple of 1/2, then 1/4, then 1/8.
     - One step per line. If more than 12 lines share a direction and level, merge them into one step ("precrease all the 1/8 vertical lines").
  3. **collapse:** all remaining creases. Title: "Collapse along the existing creases". `edges` = all M/V edges.
  4. Then any `extra_steps`, such as assembly.
- `cumulative_edges` = the union of the edges of all steps so far (this is the *sequenced crease pattern*).
- **Template text** in reference-finding language:
  - Vertical line x = a with a ≤ 0.5: "Fold the left edge to the {2a} line". Handle the right edge and horizontal lines symmetrically.
  - Midlines: "Fold in half, bottom edge to top edge".
  - Diagonals: "Fold corner to opposite corner".
  - Precrease steps add "then unfold". Valley steps say "valley fold (toward you)"; mountain steps say "mountain fold (away from you)".
- **Face tree:**
  - Root = the face containing (0.5, 0.5), or face 0 if none does.
  - BFS over face adjacency, crossing only M/V edges.
  - Each node records its `hinge_edge` and `sign` (+1 V, −1 M).
- **`folded_coords`:** for each face, compose reflections across the hinge lines along its tree path, and apply them to that face's vertices. The first face assigned wins for shared vertices.
- **Difficulty:** score = clamp(0.4·interior_vertices + 0.3·crease_count + 20·(grid level > 8) + 10·(any non-22.5° angle), 0, 100). Labels: <25 Beginner, <60 Intermediate, otherwise Advanced.
- `make_guide(fold, extra_steps=None) -> guide`, matching the contract in CLAUDE.md.

### 2e. API
- `GET /api/library`, `GET /api/library/{id}`, `POST /api/guide`.
- Precompute library guides at startup and keep them in memory.

**Acceptance**
- `pytest -q` passes, including tests that:
  - every library model validates
  - a deliberately broken CP (one flipped assignment) fails Maekawa
  - preliminary base produces 4 reference steps and 1 collapse step
  - `folded_coords` of `pleat-8` all lie within x ∈ [0, 0.125 + EPS]
- Write `frontend/src/mock/library.json` and `frontend/src/mock/model-preliminary-base.json` from real API output, so terminal B gets real data.
- Commit and push; Render redeploys automatically.

- `/guide`: Player for an uploaded CP, from the zustand store.

### Player layout
- **Left:** the 2D sequenced crease pattern (SVG) at the current step.
  - Edges in `cumulative_edges` from previous steps: light grey.
  - Current step's edges: bold M red / V blue.
  - Edges not yet made: very faint dotted.
- **Right:** 3D canvas (`@react-three/fiber`, OrbitControls, soft light, paper colours: front #f5e6c8, back #c0392b).
- **Below:** step list (clickable), current step title and text, Prev / Play-Pause / Next, a scrub slider (0–1), and "Done ✓" and "I'm stuck" buttons (the latter disabled until Phase 6).
- **Top:** progress bar and difficulty badge.

### 3D animation spec (`src/fold/animate.ts`)
- Each face is one `THREE.Mesh` (triangulate convex faces as a fan), with a double-sided material that uses different colours on front and back.
- **Collapse steps (hinge method):**
  - Process faces in BFS order.
  - `M_root = identity`.
  - `M_child = M_parent · R(axis through the hinge edge's two CP points, angle = sign · t · π · 0.98)`.
  - R = translate(−p1) → rotate about the unit axis (p2 − p1) → translate(+p1), all in CP coordinates (z = 0).
  - Add z offset = depth · 0.002 to reduce z-fighting.
  - Faces will pass through each other mid-fold. That is acceptable; label it "simplified preview".
- **Precrease / reference steps:**
  - Build a temporary 2-piece mesh by clipping the unit square with the step's `line` (Sutherland–Hodgman).
  - Rotate the piece not containing the root point about the line by `sign · π · f(t)`, where f goes 0 → 1 → 0 (fold, then unfold).
- **Fallback (flag `USE_LERP`):** interpolate each vertex from `vertices_coords` to `folded_coords` with a small z lift.
- Animation duration is 2.5s per step, with ease-in-out.

**Acceptance**
- `npm run build` passes.
- On localhost, Hub shows mock cards; clicking the preliminary base plays through all steps with visible folding.
- Commit.

## Phase 4: crease pattern detection + evaluation (terminal A)

### `app/synth.py`
- `render_fold(fold, size=800, line_px=3) -> BGR image`: white paper, M red (0,0,220), V blue (220,80,0) dashed, B black, F light grey.
- Augmentations: Gaussian noise, blur, JPEG quality 60, rotation ±5°, mild perspective warp, padding with a grey desk background.
- `make_dataset(n=40, seed=0)`: library models plus random grid CPs (random M/V lines on 8×8 and 16×16 grids and 22.5° diagonals). Saves PNG + ground-truth `.fold` to `backend/data/synth/`, which is gitignored.

### `app/detect.py`
Pipeline:
1. Resize so the longest side is 1200px.
2. Find the paper: threshold/Canny → largest 4-point `approxPolyDP` contour → warp to 1024×1024. If no quad is found, use the whole image.
3. Colour masks in HSV:
   - red: two hue ranges
   - blue
   - dark (black lines)
   - grey (F lines)
   - Morphological close joins the dashes of valley lines.
4. Per mask, run `HoughLinesP` at **multiple thresholds and minLineLength values**, because short creases fail at a single threshold.
5. Merge collinear segments (angle within 2°, distance within 6px) into maximal segments.
6. Snap each angle to the nearest multiple of 22.5° when within 3°.
7. Detect the grid: test N ∈ {4, 8, 16, 32} and pick the smallest N where ≥ 85% of endpoints are within 1.2% of the side from grid points or known 22.5° intersections. Snap endpoints to the grid.
8. Extend segment endpoints that stop just short of a crossing line or the border, then `build_fold`.
9. Confidence = mean snap residual score × fraction of vertices that pass validation.
10. Overlay: detected lines drawn on the warped image, base64 PNG.

`POST /api/detect` returns `{fold, overlay_png_b64, confidence, grid}`. Max upload size is 5MB.

### `app/eval.py` (CLI: `python -m app.eval`)
- On the synthetic dataset, match predicted to ground-truth creases (a match = same assignment, endpoints within 1.5% of the side).
- Report:
  - crease precision / recall / F1
  - M/V accuracy on matched creases
  - % of CPs that validate
  - mean runtime
  - each broken down by augmentation level
- Write `docs/eval_results.md` with a table.

**Acceptance**
- Tests: detection on 3 clean synthetic images recovers ≥ 95% of creases.
- `python -m app.eval` runs in under 2 minutes on the laptop and writes the report.
- Commit.

## Phase 6: narration, "I'm stuck", video export (terminal A)

### Backend `app/narrate.py`
- Use `google-genai` with `GEMINI_MODEL`, a 6s timeout, and an in-memory LRU cache keyed by (step text, kind, mode).
- **System prompt:** a patient origami teacher. Rewrite the step for a beginner in 1–3 short sentences using the given geometry (line position, M/V). Never invent creases.
- `mode: "simpler"` adds: explain what the paper should look like after the step, and one common mistake.
- On any error or missing key, fall back to template text, and return `source`.

### Frontend
- Narration text appears under the animation.
- "I'm stuck" calls `/api/narrate` in simpler mode and shows the result in a callout.
- A "Read aloud" toggle uses the browser's `speechSynthesis`.

### Video export (`src/fold/export.ts`)
- Record the canvas with `canvas.captureStream(30)` and MediaRecorder (webm).
- Play all steps automatically.
- Draw a title card, then for each step the step number, title and narration text as a 2D overlay. Use a composite canvas: draw the WebGL canvas plus text onto a 2D canvas each frame and record that one.
- Download as `<model>-guide.webm`. Show progress while recording.

**Acceptance**
- With no key, narration still shows template text.
- With a key, text comes back from Gemini.
- Export produces a playable webm for the preliminary base.
- Commit.
